# WSET Quiz 🍷

A bilingual (EN/DE) multiple-choice quiz for **WSET Level 1 and Level 2** exam prep, with 503 questions on regions, wine styles, grape varieties, labelling, vineyard and winemaking, sparkling, sweet and fortified wines, food pairing and service.

The question bank follows the official [WSET Level 2 Award in Wines specification](https://www.wsetglobal.com/media/13167/wset_l2wines_specification_en_may2023_issue2.pdf) (Issue 2, 2023). Questions on grapes, regions or terms outside that syllabus have been moved to `archive/questions-beyond-l2.json` (with the reason for each). The app doesn't load that file.

It's plain HTML, CSS and JavaScript: no build step, no backend, no database. Each quiz draws a random set of questions from `questions.json`.

> Not affiliated with or endorsed by the Wine & Spirit Education Trust (WSET). The questions were written for self-study; check anything surprising against the official course material.

## Library

`library.html` (the **Library / Bibliothek** tab) has a profile for every grape variety and wine in the Level 2 syllabus:
the 8 principal grapes, 22 regionally important grapes, 3 sparkling-wine grapes and 7 sparkling or fortified wines.
Every profile has the same layout:

- **Key facts:** the points to remember.
- **Structure:** colour, sweetness, acidity, tannin, alcohol and body on the WSET 5-step scale (low → high), shown as colour-coded meters. Ranges cover the typical styles.
- **Aromas:** primary (green), secondary (amber) and tertiary (brown).
- **Countries & regions:** exactly the GIs the specification names for that grape.
- **Label terms:** the label terms that go with the grape or wine.

The overview groups the profiles by learning outcome and has search across names, regions and aromas in both languages.
Tile colours show the kind: burgundy for black grapes, gold for white, blue for sparkling, brown for fortified.
Profiles have their own URLs (e.g. `library.html#/syrah`).

The data lives in `library.json`, generated by `tools/make_library.py`. Edit the script, then run `python3 tools/make_library.py`.

## Training

`trainer.html` (the **Training** tab) drills the one skill the exam tests most: telling the grapes apart by their style.

- **Blind profile:** see structure meters and aromas without a name, then pick the grape from four. The difficulty levels are:
  - *Easy*: the wrong options are clearly different grapes.
  - *Hard*: the wrong options are the grapes with the most similar profile.
  - *Exam*: structure only, no aromas.
- **Head-to-head:** two grapes, one question, e.g. "Which has more tannin?". It's only asked where their ranges don't overlap, so there's always one clear answer.
- **Build the profile:** you see a grape name and set every structure row on the 5-step scale, then pick its 3 typical aromas from 8.
  Each row is marked ✓, "≈ one step off" or ✗, next to the correct range.
- **Aroma sorting:** rare signature aromas ("which grape is quince typical of?"), or "is this aroma primary, secondary or tertiary?".
- **Mix:** all four drills in turn, the most varied way to train.
- **Spot-the-difference feedback:** after every answer, you see both profiles side by side with the differing rows highlighted, plus each grape's "How to recognise it" cue.
- **Confusables deck:** every mix-up is stored and comes back after 2, 5 and 12 questions, until you've answered it right three times in a row.
- **Progress:** each library tile shows a ring with your trainer score for that grape. Progress is saved in the browser on this device only.

Questions are generated from `library.json`, so there are no separate training questions to maintain.

## Features

- Filter by level (L1, L2 or both), by country (France, Italy, Spain, …) and by topic. The filters combine.
- Questions and answer options are shuffled for every quiz.
- Instant feedback with an explanation. Keyboard: `1`–`4` to answer, `Enter` for the next question.
- The result screen scores you against the WSET pass mark (55%) and lists every missed question. "Retry missed" drills those again.
- The EN/DE toggle works at any time, even mid-question.
- Installable as an app (PWA) and works offline after the first visit.

## Install on your phone

Open the GitHub Pages URL in **Chrome on Android**, then tap **⋮ → Add to home screen** (or **Install app**).
It opens full-screen like a normal app and works without a connection.
On iPhone, use Safari: **Share → Add to Home Screen**.

When you're online, the app always loads the latest questions. Offline, it uses the copy from your last visit.

the local browser storage and your rights, and has a button to delete the stored data.

## Publish on GitHub Pages

The workflow in `.github/workflows/pages.yml` validates `questions.json` and deploys the site on every push to `main`.
Pull requests only run the validation.

One-time setup:

1. Create an empty repository on GitHub and push this folder to its `main` branch:
   ```bash
   git init -b main
   git add .
   git commit -m "Initial commit"
   git remote add origin git@github.com:<you>/<repo>.git
   git push -u origin main
   ```
2. In the repository, go to **Settings → Pages → Build and deployment** and set **Source** to **GitHub Actions**.
3. Re-run the workflow (**Actions → Deploy to GitHub Pages → Run workflow**), because the first push ran before Pages was enabled.

The site is then live at `https://<you>.github.io/<repo>/`.

Pages works for public repositories on free accounts. For private repositories it needs a paid plan.

## Run locally

Either serve the folder with Python:

```bash
python3 -m http.server 8790
```

or use Docker Compose (`podman compose` works too):

```bash
docker compose up -d --build
```

Then open http://localhost:8790. Opening `index.html` directly doesn't work, because browsers block `fetch()` on `file://`.
The container copies the files into the image, so rebuild after every change.

## Questions

Each entry in `questions.json` is one question, in both languages:

```json
{
  "id": "l2-041",
  "level": 2,
  "topic": "Regions",
  "countries": ["Italy"],
  "answer": 0,
  "en": { "question": "…", "options": ["…", "…", "…", "…"], "explanation": "…" },
  "de": { "question": "…", "options": ["…", "…", "…", "…"], "explanation": "…" }
}
```

- `answer` is the index of the correct option and applies to both languages, so `de.options` must be in the same order as `en.options`. The app shuffles the options when it shows them.
- `topic` is one of: Wine Types, Wine Styles, Grape Varieties, Viticulture, Winemaking, Tasting, Food & Wine, Service & Storage, Regions, Geography, Sparkling, Sweet & Fortified, Labelling. A new topic also needs its German name in `TOPICS_DE` in `app.js`.
- `countries` is optional. It lists the country (or countries) the question is about, and drives the country filter. Allowed names are in `COUNTRIES` in `app.js` and `validate.py`.

Check the files after you edit them (CI runs the same check, which also covers `library.json`):

```bash
python3 validate.py
```
